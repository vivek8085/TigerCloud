# Tiger Cloud Data Projects

This repository contains two Python projects demonstrating real-time financial data ingestion and AI-powered semantic search using Tiger Cloud (TimescaleDB).

## Projects

### 1. Tiger Cloud Real-Time Financial Data Pipeline

**Overview**

A Python data ingestion pipeline that streams stock price events from the Twelve Data WebSocket API into Tiger Cloud (TimescaleDB).

**Technologies**
- Python
- Twelve Data WebSocket API
- PostgreSQL
- TimescaleDB hypertables
- `psycopg2`
- `python-dotenv`

**Database**

The `stocks_real_time` hypertable stores:
- Timestamp (`time`)
- Stock symbol (`symbol`)
- Stock price (`price`)
- Daily volume (`day_volume`)

**Setup**

1. Install Python and create a virtual environment.
2. Install the dependencies listed in `requirements.txt`.
3. Configure the required environment variables locally in a `.env` file.
4. Create the `stocks_real_time` table and convert it into a hypertable in Tiger Cloud.
5. Run the pipeline:

   ```bash
   python pipeline.py
   ```

**Verify financial data**

Run this query in the Tiger Cloud SQL Editor:

```sql
SELECT time, symbol, price, day_volume
FROM stocks_real_time
ORDER BY time DESC
LIMIT 20;
```

### 2. AI-Powered Vector Search with Tiger Cloud

**Overview**

A Python application that generates text embeddings using a Sentence Transformers model, stores them in Tiger Cloud, and retrieves semantically similar documents using pgvector.

**Technologies**
- Python
- Sentence Transformers
- PostgreSQL
- Tiger Cloud / TimescaleDB
- pgvector
- `psycopg2`
- `python-dotenv`

**Database**

The `document_embeddings` hypertable stores:
- Document ID (`id`)
- Creation timestamp (`created_at`)
- Document category (`category`)
- Document text (`content`)
- 384-dimensional embedding vector (`embedding`)

**Setup**

1. Install the dependencies listed in `requirements.txt`.
2. Enable the pgvector extension in Tiger Cloud:

   ```sql
   CREATE EXTENSION IF NOT EXISTS vector;
   ```

3. Create the document embeddings table and hypertable:

   ```sql
   CREATE TABLE IF NOT EXISTS document_embeddings (
       id BIGINT GENERATED BY DEFAULT AS IDENTITY,
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       category TEXT NOT NULL,
       content TEXT NOT NULL,
       embedding VECTOR(384) NOT NULL
   );

   SELECT create_hypertable(
       'document_embeddings',
       'created_at',
       if_not_exists => TRUE
   );
   ```

4. Configure the required database environment variables locally in a `.env` file.
5. Run the vector search application:

   ```bash
   python vector_search.py
   ```

   The application generates embeddings, inserts sample documents, and searches for documents similar to the supplied natural-language query.

**Verify vector data**

```sql
SELECT
    id,
    created_at,
    category,
    content,
    vector_dims(embedding) AS dimensions
FROM document_embeddings
ORDER BY created_at DESC
LIMIT 10;
```

**Search for similar documents**

```sql
SELECT
    id,
    category,
    content,
    embedding <=> '[0,0,0]'::vector AS distance
FROM document_embeddings
WHERE category = 'technology'
ORDER BY embedding <=> '[0,0,0]'::vector
LIMIT 5;
```

Replace the example vector with a real 384-dimensional embedding generated by the model for meaningful similarity results. The Python application performs this search automatically using the query embedding.

## Environment Variables

Create a local `.env` file for the credentials and API keys required by each project. Use the variable names expected by the corresponding Python scripts.

**Important:** Never commit `.env`, API keys, passwords, or database credentials to GitHub. Add `.env` and `.venv/` to `.gitignore`.
